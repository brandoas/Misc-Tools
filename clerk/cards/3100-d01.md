## Task 2 - IPv4 Deployment and Connectivity (10)

tasks: [2]
objective: Use standard network documentation tools to prove the IPv4 network is fully functional.

### Evidence

- A network diagram is present and matches the physical topology in the handout
- VyOS-1 eth0 is the WAN interface, eth1 is LAN1, eth2 is LAN2
- Ubuntu-GUI has a static IPv4 address
- Ubuntu-GUI has no DNS configured at this stage
- A ping from Ubuntu-GUI to its gateway succeeds, with output shown

## Task 3 - SLAAC and DHCPv6 on the WAN (10)

tasks: [3]
objective: Prove that SLAAC, DHCPv6, and IPv6 Routing properly function.

- eth0 shows an autoconf address acquired by SLAAC
- eth0 shows a separate DHCPv6 address
- The autoconf address and the DHCPv6 address are distinguished from each other
- A ping6 to 2606:4700:4700::1111 succeeds, with output shown

- show interfaces pasted with no analysis
- Link-local mistaken for a global address
- Addresses listed without naming the acquiring mechanism

## Task 6 - Router Advertisements on LAN1 (15)

tasks: [6]
objective: Properly configure and observe the SLAAC router-advertisement for LAN1, and dual stack networking within the DHCP transport protocol.

### Evidence

- router-advert is configured on eth1 with a prefix
- Both name servers are included in the router advertisement
- A packet capture on the LAN1 link shows RA packets
- nmcli output showing the Ubuntu-GUI address is present
- The client address is tied to the prefix carried in the RA

- dig SERVER line not discussed

## Task 7 - IPv6-Only Network and NAT64 (20)

tasks: [7]
objective: Setup an IPv6 only network and observe the function and limitations.

### Evidence

- router-advert is configured on eth2 with the DNS64 name server
- A nat64 rule is present in the configuration
- A ping from Windows to www.ohio.edu shows a 64:ff9b:: address
- A capture on the VyOS-1 WAN link is present
- A capture on the VyOS-1 LAN2 link is present
- The ICMP request and reply are shown both before and after translation
- The translation is explained from the captures, not asserted
- A ping to 8.8.8.8 from the IPv6 only host is shown failing
- The reason a literal IPv4 address never reaches DNS64 is stated

- CLAT is tied to the PREF64 option in the router advertisement
- A credible technical reference is cited

- Only one side of the translation captured
- Captures pasted with no explanation
- 464XLAT copied rather than explained
- Reference missing or not technical
