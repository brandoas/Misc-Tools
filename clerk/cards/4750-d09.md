## Task 1 - Resources and Construction Ticket (15)

tasks: [1]
objective: Obtain an AS number and provider-independent addresses from DRIR, order your connection through the ISP portal.  Document the findings.

### Evidence

- AS number recorded as assigned by DRIR
- IPv4 provider-independent allocation recorded from DRIR
- IPv6 provider-independent allocation recorded from DRIR
- ISP portal construction ticket shown as submitted
- One Word document submitted
- Fixed width type used for CLI output and captures, and only for those
- Every block of output tied to the command and the router that produced it

### Critique

- AS number or an allocation missing from the documentation
- Construction ticket never shown as submitted
- CLI output pasted with no fixed-width formatting
- Output not attributed to a command or device

## Task 2 - Connect to Your ISP (19)

tasks: [2]
objective: Provision connectivity to an ISP in NESTNET.

### Evidence

- CPE port built with `ducky.sh cpe-up`
- A Cloud node in GNS3 connects br-cpe1 to the VyOS-1 WAN interface
- VyOS-1 WAN interface addressed from the ISP portal's connection data
- A successful ping to the ISP's gateway address from VyOS-1
- A LAN built from the first /24 and /64 of the allocation, VyOS-1 on the first address of each and Ubuntu-CLI on the tenth
- Ubuntu-CLI can ping VyOS-1, with VyOS-1 set as its default gateway
- VyOS-1 WAN interface MTU reduced to 1450

### Critique

- WAN interface addressed from guessed or invented values instead of the portal data
- Ping to the ISP gateway never shown
- LAN addressed from the wrong allocation or the wrong host numbers
- MTU change omitted

## Task 3 - Establish the BGP Session (19)

tasks: [3]
objective: Establish an eBGP session with your ISP over the CPE connection, for IPv4 and IPv6, using your AS number.

### Evidence

- A PERMIT-ALL route map created
- BGP configured with the student's own AS number
- An IPv4 neighbor session configured to the ISP's AS and gateway address
- An IPv6 neighbor session configured to the ISP's AS and gateway address
- `show bgp summary` showing both sessions established
- A packet capture on the CPE link, after a session reset, identifying the OPEN, KEEPALIVE and UPDATE messages

### Critique

- Only one address family's session shown
- `show bgp summary` omitted or shown before the session came up
- Capture taken without resetting the session, so no OPEN message appears
- BGP messages in the capture not identified by type

## Task 4 - Announce Your Allocation (15)

tasks: [4]
objective: Announce your whole IPv4 and IPv6 allocation to your ISP and confirm the ISP is sent exactly what you intend.

### Evidence

- A blackhole static route created for the IPv4 allocation
- A blackhole static route created for the IPv6 allocation
- Both allocations announced under the BGP address families
- Advertised routes shown to the ISP for IPv4
- Advertised routes shown to the ISP for IPv6
- The routing table entry for the IPv4 allocation shown with its next hop and protocol
- A 1472 byte ping with the Do Not Fragment bit confirms fragmentation at the reduced MTU

### Critique

- Only one address family announced or verified
- Advertised-routes output missing for one or both families
- Next hop or protocol absent from the route table entry
- The DF-bit fragmentation test omitted

## Task 5 - Read the Routes from Your ISP (20)

tasks: [5]
objective: Explain what the routes from your ISP say about the path to each destination, and trace the path through your ISP to a diversity of locations.

### Evidence

- IPv4 BGP table prefix count recorded
- IPv6 BGP table prefix count recorded
- AS path and origin AS recorded for 96.25.0.0/16
- AS path and origin AS recorded for 128.200.0.0/16
- Route to 8.8.8.8 shown with its protocol, prefix and next hop
- Ping and traceroute to an ITS DNS server compared against the advertised routes
- A classmate's AS number and allocation looked up in DRIR
- A matching BGP entry, ping and traceroute recorded for the classmate's allocation

### Critique

- A prefix count given for only one address family
- AS path recorded for only one of the two named prefixes
- The 8.8.8.8 route missing its next hop or protocol
- The classmate comparison skipped entirely
- Ping or traceroute shown but never compared against the BGP data

## Task 6 - Thought Questions (12)

tasks: [6]
objective: Document the final router configuration and explain the behavior observed in this lab.

### Evidence

- Final VyOS-1 configuration included
- The number of autonomous systems between the student and each recorded prefix's origin explained
- What the router knows about other paths to those prefixes explained
- What the ISP would accept for a prefix announced outside the student's allocation explained
- The changes needed to connect to a second ISP described
- Which of the recorded outputs would differ with a second ISP connection identified

### Critique

- Final configuration omitted
- AS count given with no reference to the recorded AS paths
- Out-of-allocation behavior answered without addressing what the ISP would accept
- Second-ISP answer restates the lab instead of describing a change
