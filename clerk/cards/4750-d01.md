## Task 5 - Client Setup and Testing (5)

tasks: [5]
objective: Show additional configuration recipes and proof that the system works.

### Evidence

- Client configuration shown for each client
- Ubuntu client addressing set with a persistent tool, not a temporary one
- Client reaches its gateway
- Client proof for both IPv4 and IPv6
- Commands shown are ones the client OS could actually run

### Critique

- `ip addr add` used on an **Ubuntu** client instead of `nmcli`. The address does not survive a reboot, so the recipe does not reproduce and the next lab starts with missing addressing and no obvious cause. This does NOT apply to VPCS, where `ip` is the native command and there is no NetworkManager: VPCS syntax is `ip 192.168.1.1/24 192.168.1.254`, with no `sudo`, no `addr add` and no `dev ensN`
- `nmcli` used on some Ubuntu clients and `ip addr add` on others, which is worse than either: part of the network persists and part does not
- Windows commands that could not have run, for example `eth2` on Windows
- Only one address family proven from the clients
- Item 21 hosts failing to reach the internet is expected. No deduction.
