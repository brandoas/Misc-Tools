## Task 1 - URL Basics (5)

tasks: [1]
objective: Use the following steps to demonstrate knowledge of the structure of URLs.

### Evidence

- Working http URL built on their own hwr DNS name
- That URL shown bare in the browser
- Port 80 listener identified with ss (process named, not just the port)

### Critique

- Someone else's vm number in the URL or prompt
- ss output pasted with the owning process never identified

## Task 2 - Web Server Basics (10)

tasks: [2]
objective: Student will demonstrate that they can manipulate the base structure of a web server's web root and access HTTP content from the command line.

### Evidence

- Web root located and its contents changed (default nginx page replaced or moved)
- HTTP content fetched from the command line (curl or wget) with output shown
- The connection between the file on disk and the response over the wire stated

### Critique

- Screenshots of a browser where the command line was asked for
- Web root edits shown without the resulting HTTP fetch

## Task 3 - A Basic HTML Page (10)

tasks: [3]
objective: Build a basic HTML page and serve it from the web server.

### Evidence

- Page authored by the student, valid basic structure (html, head, title, body)
- Served from their own web server at their hwr name, not opened as a local file
- Page visibly theirs (name, VM number, or other personal content)

### Critique

- Boilerplate page with no personal content
- file:// URL in the browser bar instead of the server URL

## Task 4 - Web Based Debugging (15)

tasks: [4]
objective: Observe both the browser's interaction with the server and the underlying network traffic that makes the page appear.

### Evidence

- Browser developer tools view of the request/response for their page
- Packet capture of the same exchange, tied back to what the browser showed
- Explanation connects the two views: same conversation, two vantage points

### Critique

- Devtools screenshot with no capture, or capture with no reading of it
- Capture of someone else's addresses

## Task 5 - A Publicly Trusted Certificate (20)

tasks: [5]
objective: Acquire a Let's Encrypt free, automated, public certificate provider using the Certbot software.

### Evidence

- Certbot run against their hwr name with the issuance shown
- The site served over HTTPS with the browser trusting it (no warning)
- Certificate details shown (issuer Let's Encrypt, their subject name)

### Critique

- Self-signed certificate presented as the result
- HTTPS shown but the certificate never inspected
- Issuance output pasted with someone else's domain in it

## Task 6 - Layer 7 Routing (20)

tasks: [6]
objective: Route requests to different services by URL through nginx, and prove what the application behind the proxy can and cannot know about the client.

### Evidence

- nginx routing by URL to more than one backend service, config shown
- Both routes demonstrated working from a client
- The proof: what the proxied application sees about the client (and what it cannot), backed by the application's own logs or output

### Critique

- Routing shown but the client-visibility question ignored
- Proxy config pasted without a working demonstration
- Claims about headers with no evidence from the backend side
