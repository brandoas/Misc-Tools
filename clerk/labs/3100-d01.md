## Task 1 - Network Design and Documentation

Graded in the PreLab, not on this card. IPGrid, network diagram, and VyOS
configuration recipe.

## Task 2 - Deploy

Objective: Use standard network documentation tools to prove the IPv4 network is fully functional.

Steps 1 to 4.

2. Set up objects and connections as shown in the physical diagram.
3. Start the VyOS router, but do not start the client machines yet.
4. On Ubuntu-GUI-1 configure IPv4 settings WITHOUT DNS. Confirm local
   connectivity with `ping <gateway IP>` and Internet connectivity with
   `ping 8.8.8.8`.

## Task 3 - IPv6 router WAN configuration with SLAAC

Objective: Prove that SLAAC, DHCPv6, and IPv6 Routing properly function.

Steps 5 to 10.

5. Configure the WAN interface on VyOS-1 with an autoconfiguration address:
   `set interfaces ethernet eth0 ipv6 address autoconf`
6. Validate IPv6 connectivity: `ping6 2606:4700:4700::1111`
7. View the IPv6 route table: `show ipv6 route`
8. Acquire a DHCPv6 address on the WAN interface:
   `set interfaces ethernet eth0 address dhcpv6`
9. Confirm `ping6 2606:4700:4700::1111` still works.
10. Use `show interfaces` to show the configured interface addresses. Analyse
    the different portions of each address and describe the process VyOS used to
    acquire each of them.

## Task 4 - IPv6 on the LAN interfaces with DHCP-PD

Objective: Properly configure and gather associated network data on the DHCP-PD protocols.

Steps 11 to 12.

11. Configure DHCP-PD on the WAN interface, delegating to both LAN interfaces:

    set interfaces ethernet eth0 dhcpv6-options pd 0 length 62
    set interfaces ethernet eth0 dhcpv6-options pd 0 interface eth1 address 1
    set interfaces ethernet eth0 dhcpv6-options pd 0 interface eth1 sla-id 0
    set interfaces ethernet eth0 dhcpv6-options pd 0 interface eth2 address 1
    set interfaces ethernet eth0 dhcpv6-options pd 0 interface eth2 sla-id 1

12. Use `show interfaces` to show the new interface addresses. Analyse the
    different portions of each new address and describe the process VyOS used to
    acquire each of them.

## Task 5 - IPv6 and DNS

Objective: Demonstrate the interactions between DNS and IPv6 protocols.

Steps 13 to 14.

13. The VyOS router uses Ohio University IPv4 caching name servers by default,
    so it transports the DNS request over IPv4 even while carrying IPv6 records,
    as the ping to google shows:

    show configuration commands | match name-server
    ping google.com

14. Change the DNS configuration to use the ITS IPv6 DNS servers:

    delete system name-server
    set system name-server 2610:a8:4831:300::10
    set system name-server 2610:a8:4831:300::11

## Task 6 - IPv6 Router Advertisements to configure client machines

Objective: Properly configure and observe the SLAAC router-advertisement for LAN1, and dual stack networking within the DHCP transport protocol.

Steps 15 to 18.

15. Configure router advertisements on eth1, including DNS for the client:

    set service router-advert interface eth1 prefix ::/64
    set service router-advert interface eth1 name-server '2610:a8:4831:300::10'
    set service router-advert interface eth1 name-server '2610:a8:4831:300::11'

16. Start a packet capture in GNS3 on the link between Ubuntu-GUI and VyOS.
    Power on Ubuntu-GUI. It forms an address using the RA for the network
    portion and either an EUI-64 or an RFC 7217 privacy client portion.
17. Use `nmcli` to get the interface address on Ubuntu-GUI and show the
    relationship of that address to the SLAAC packets in the capture.
18. Use `dig www.ohio.edu @2610:a8:4831:300::10` to show an IPv4 A record
    received over IPv6 transport. Note the SERVER line at the bottom, which
    names the IPv6 address that answered. Run the same command without the `@`
    and compare: Ubuntu answers from 127.0.0.53, its local stub resolver, which
    hides which server really did the work.

## Task 7 - DNS64/NAT64 Transition technologies

Objective: Set up an IPv6 only network and observe the function and limitations.

Steps 19 to 24.

19. Configure router advertisements on eth2 with the DNS64 name server:

    set service router-advert interface eth2 prefix ::/64
    set service router-advert interface eth2 name-server 2001:4860:4860::6464

20. Enable NAT64: `set nat64 source rule 1 source prefix 64:ff9b::/96`
21. From the Windows PC, ping the IPv4 only `www.ohio.edu` and note the
    translated address.
22. Start Wireshark captures on the WAN and LAN2 interfaces of VyOS-1 and
    capture an ICMP ping packet and its response, pre and post NAT64.
    Demonstrate understanding of the process with these captures.
23. On the Windows PC run `ping 8.8.8.8`. There is no perfect solution.
24. Find a credible technical reference for 464XLAT and its relationship to the
    PREF64 SLAAC option. Describe in your own words how that function works.
