## Task 1 - Build the Network

Objective: Build the network with the lab script, then inspect what it built and bring up the ONOS controller and the Open vSwitch fabric.

1. Clone the GitHub repo.
2. Run `ducky.sh build` with the VyOS-1 WAN address to build, start and configure the network. Open the GNS3 project and look at what it built.
3. Open the ONOS web interface, user `onos`, password `rocks`.
4. Review the fabric in the topology viewer: five Open vSwitch switches inside Mininet-1 (spine1, spine2, leaf1, leaf2, leaf3), each leaf with one link to each spine, spines connecting only to leaves.
5. Observe each Ubuntu-CLI host's address and default route.

## Task 2 - Reactive Forwarding

Objective: Demonstrate a network that forwards everything while the reactive forwarding application runs.  Describe the relationship of real world traffic to the follows in the controlled network.

6. Connect to the ONOS command line and list the active applications (`apps -s -a`).
7. From each Ubuntu-CLI host ping the other two hosts and 8.8.8.8.
8. In the ONOS web interface observe the hosts on the topology map.
9. In the ONOS command line list the hosts and the flow rules on each switch (`hosts -s`, `flows -s`). The identifier of a host is the `id` at the start of its line.

## Task 3 - Move to Intent Based Flows

Objective: Demonstrate fowarding with flows instead of generic ethernet forwarding.  Analyze the difference between flows and intents.

10. In the ONOS command line deactivate the reactive forwarding application (`app deactivate org.onosproject.fwd`).
11. Repeat the pings. Failure is an option.
12. In the ONOS command line list the hosts (`hosts -s`).
13. Install a host-to-host intent between Ubuntu-CLI-1 and Ubuntu-CLI-2, then list the intents.
14. From Ubuntu-CLI-1 ping Ubuntu-CLI-2 and 8.8.8.8.
15. Install a host-to-host intent between Ubuntu-CLI-1 and the VyOS-1 fabric address, then list the intents.
17. Test connectivity between the hosts and observe the intents in the ONOS web interface and CLI. List the flow rules on each switch (`flows -s`).

## Task 4 - Link Failure

Objective: Demonstrate how an installed intent responds to the loss of a link. Describe what the ping does and what ONOS changes in the flow rules.

18. On Ubuntu-CLI-1 start a continuous ping to Ubuntu-CLI-2.
19. In the ONOS web interface open the Intents view, select an intent and show its path on the map (press `h` for hosts, `l` for device labels). Select intents until the dashed path ends at Ubuntu-CLI-1 and Ubuntu-CLI-2, and note the spine it crosses (`of:...11` is spine1, `of:...12` is spine2).
20. Open the Mininet prompt on Mininet-1.
21. At the Mininet prompt take down the link between leaf2 and that spine (`link leaf2 <spine> down`).
22. Observe the ping, then list the intents and the flow rules on each switch again.
23. At the Mininet prompt bring the link back up (`link leaf2 <spine> up`), then leave the session.
