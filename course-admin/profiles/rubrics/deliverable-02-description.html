Design, build, and verify a five-router, dual-stack network, first with static routing and then with OSPF as the interior gateway protocol. Document the design, prove it works on both IPv4 and IPv6, observe how OSPF reacts to a link failure, and answer the thought questions. Submit one lab report covering all six tasks of Lab 2 (Advanced Routing).

Every network in this lab is dual-stack, so every design element and every verification step must be shown for both IPv4 and IPv6.

What to submit

A single Word document (.docx) uploaded here, organized in task order and containing:

  1. IP design and documentation: a completed IP Address Grid for all nets, the loopbacks, and the WAN, following the course IP conventions. Point-to-point links use /30 (IPv4) and /64 (IPv6). Router IDs follow the stated convention. Client LANs use DHCP and SLAAC.
  2. A logical network diagram, drawn (Draw.io or Visio), customized to your IP design, with network numbers and interface addresses labeled. Not a GNS3 screenshot.
  3. Configuration recipes for the static build and the OSPF build, including loopback addressing on every router and default-route origination on the edge router only.
  4. Static-routing proof (Task 2): from each router, pings to every other router's IPv4 and IPv6 loopback, plus the full route tables.
  5. OSPF verification (Task 4): the neighbor, interface, database, and route outputs for both families, with your reading of them, and client-to-client traceroutes.
  6. Link-failure analysis (Task 5): the before and after traceroutes, with the path change identified and explained.
  7. Thought questions (Task 6): the OSPF failure-and-recovery explanation and the compare-and-contrast of three eligible VyOS routing protocols.

Format conventions (these are graded)

  • Word document (.docx) only. Canvas enforces the extension.
  • Diagrams are drawn, not GNS3 screenshots, except where a result can only be shown in a GUI.
  • CLI, route-table, and traceroute output uses a fixed-width font, or it is unreadable and will lose credit.
  • Answer what is asked. Show the relevant lines only. Do not pad the report with output that was not requested.
  • Follow the class IP allocation conventions and cite any diagram or material that is not your own.

Grading uses the attached rubric. Review it before you start.
